## Cloudflare R2 — done, and serving

Books live in R2 and are served from there. Verified on 26 Aug: the site
answers `/api/library/pdf` with `/api/library/file?key=…`, that returns
the PDF (200, correct bytes, `application/pdf`), and range requests
answer 206 so PDF.js can page through large books.

- Bucket `library`, bound to the Pages project as **`LIBRARY_BUCKET`**.
- **All 221 books copied**, 0 failed, **2032 MB** in the bucket.
- **[functions/api/library/file.ts](../functions/api/library/file.ts)**
  serves the bytes, enforcing the same visibility rules as before (anon →
  public only, members → non-hidden, admins → everything; `catechism/`
  keys follow the lesson rules).
- **[functions/api/library/pdf.ts](../functions/api/library/pdf.ts)** and
  **[functions/api/catechism/pdf.ts](../functions/api/catechism/pdf.ts)**
  check R2 first and fall back to a Supabase signed URL for anything not
  there — so a partial copy is safe, and nothing broke during the move.
- **[functions/api/admin/library/copy-to-r2.ts](../functions/api/admin/library/copy-to-r2.ts)**
  copies one book per request; the "Copy books to Cloudflare" button on
  `/admin/library/` works through the catalogue and is resumable.

**The Supabase copies are still there and should stay** until the R2 path
has had a few days of real use. Deleting them is what frees the old

## 26 August — the MEGA import, done

**Every book from the MEGA archive is now in R2.** Measured from the
bucket afterwards:

| | |
|---|---|
| Files in the bucket | **691** |
| Size | **8.06 GB** of the 10 GB free allowance |
| Headroom | ~1.9 GB |

Going over the allowance is not a cliff — about 1.5 cents per GB-month —
but there is no need: MEGA is the parish's only free archive, so the
library isn't expected to grow much beyond this.

**How books get in, without handing over a database key:**

1. `node scripts/list-mega-folder.mjs "<link>" --download library-incoming/<dir> --folder "<name>"`
   pulls a folder from MEGA (decrypts it; no account, no install).
   `scripts/fetch-mega-batches.sh` does every missing folder in order.
   **Beware `--folder ""`** — an empty filter matches all 8.6 GB.
2. `node scripts/push-to-r2.mjs library-incoming` puts the PDFs in the
   bucket — files only, six at a time, streaming anything over 100 MB
   (reading a 856 MB book into memory is what failed the first attempt).
   Skips filenames already in the bucket, so it never overwrites an
   existing book. Needs `scripts/r2-credentials.json` (git-ignored,
   already created and working; the token is scoped to the `library`
   bucket alone).
3. On `/admin/library/` → **Library jobs** → **"Add books found in
   storage"** → `POST /api/admin/library/register-storage` finds bucket
   files with no catalogue row and writes them as **Hidden**, using the
   server's own Supabase key. Batches of 50, loops until done.
4. **"Prepare text"** then gives them text and page numbers in the
   browser, as before. Slow with hundreds of books; resumable.

Local copies of everything are in `library-incoming/` (6.5 GB, 479
PDFs) — a second home for the archive, and the input if shrinking is
ever wanted.

**Still to do:**
- Titles come from filenames and are only as good as those; every
  imported book lands in category **Other**. Correcting these is manual
  today — a bulk category edit may be worth writing.
- There are **duplicates**: the same book from the old library and from
  MEGA under different filenames, e.g. *Orthodox Apologetic Theology* and
  *Andreyev-Orthodox Apologetic Theology*, and three pairs of the
  Ante-Nicene Fathers. Harmless, but they clutter a search.
- 1 book is still skipped as a slug collision.
- The 13 books whose text couldn't be read at all.
- Shrinking: the tooling works (about 3x on books stored as lossless
  images) but was not used for this import. Revisit only if space gets
  tight. It still can't shrink 600-DPI bilevel scans — 87 MB -> 59 MB was
  the best it managed, and keeping them 1-bit didn't help.
- Supabase still holds the original 221 books; deleting them frees that
  allowance, but only once R2 has proven itself over a few days.

## 29 August — the import finished, and three bugs behind it

**The catalogue is complete: 690 books, all visible to parishioners.**
Registration is done ("Add books found in storage" reports nothing
left), and every book that has readable text now has it.

Three things were wrong, and all three are fixed:

### Text wouldn't save — 28 books, "unsupported Unicode escape sequence"
The backfill said *27 with text, 28 failed*, which is the shape of a
problem that isn't where it looks. Extraction was fine; the **save** was
failing. Some PDFs yield NUL characters and lone surrogates — legal in a
JavaScript string, illegal in a Postgres text column — and one stray
code unit rejects the entire book.
[src/lib/library-text.ts](../src/lib/library-text.ts) strips them, and
both save paths (upload form and backfill) call it.

### Search dead-ended on a book half-remembered
"Ivan Andreyev, Orthodox Apologetic Theology" found nothing, though the
book is right there. Two causes:
- **Punctuation wasn't folded**, so the term was `andreyev,` with the
  comma attached and it matched nothing. This alone was the whole
  failure for that book.
- **Every word had to appear.** Right when it works, but the catalogue
  files many books under a title alone, so naming the author guaranteed
  an empty page. Now, when nothing carries every word, the books
  carrying the most are shown and the count says so. **At least two
  words must land** before loosening — one word out of four is not a near
  miss, it's "there" containing "here", and a wrong book is worse than
  none.

### 662 books were invisible
Everything imported landed Hidden, so members saw 28 books out of 690.
All are now visible to anyone signed in — not to the open web.

### Getting the library to a Claude that can't sign in
The export control on `/admin/library/` now offers three things, and
exports whatever the table is showing, so a search narrows it first:
- **Spreadsheet (.csv)** — the catalogue
- **Reading list (.md)** — grouped by category, one line a book, saying
  whether each has text and page numbers
- **Full text of these books (.txt)** — the whole text of everything
  showing, in one file, with page markers made readable

A Claude that can drive Tina's browser needs none of that: it reads the
library through her own sign-in, the same way this session did. It's
Claude Cowork — its own browser in the cloud, no session — that needs
the files.

## Built on 24–25 August

### Catechism lessons — migrations 012, 014
`/admin/catechism/` uploads a lesson PDF; it appears at once under **My
Learning** on `/account/`, read at `/account/lesson/?slug=…`. Optional
"Email members" announces it to everyone opted into communications —
sent in the background, one address per message, paced for Resend's rate
limit. Posted/draft states; `catechism_lessons` table.

### Parish mailer — migrations 013, 014
`/admin/email/` writes to one member, several, or everyone with an
account. Any message with more than one recipient is addressed TO the
parish identity with everyone on **BCC** (recipients can read a To
header, so this is a privacy matter, not a nicety), batched at 49 per
message. A **Send as** dropdown picks the parish office or Fr. Antonios,
which sets From, Reply-To and the visible To. Every send is recorded in
`parish_emails`. Deliberately ignores `opt_in_communications` —
registration is the permission; that flag governs only the automatic
lesson announcements.

### Two hubs
`/admin/` and `/account/` both: a quick-jump bar over folding sections
that remember what you leave open, jumps that land instantly rather than
gliding (`<html data-instant-scroll="true">`, which the layout's
back-to-top button honours).

### Calendar fasting banner
Above the date: fast day / fish allowed / no fast, with the season and
rule, parsed from the Holy Trinity calendar's own `headerfast` line —
the parish and the calendar app can never disagree. Season and rule split
at the **last** ". " because "Nativity (St. Philip's Fast)" contains one.

### Library
- **Search** on `/learn/library/` (title, author, description, category,
  language; multi-word any order; accents fold) and on `/admin/library/`
  with filters for visibility and text state.
- **Text extraction** — migration 015. Each PDF's text is pulled out *in
  the admin's browser* with PDF.js at upload, and stored. A backfill
  button does books uploaded earlier. Scans yield nothing and are marked
  `text_status = 'empty'` so they're never retried; **13 books** failed
  outright (filter: "Failed to read").
- **Page numbers** — migration 016. Extraction writes `␞label|pdfPage␞`
  markers using the PDF's own page labels where present, so a citation
  gets the *printed* page (a book's page 3 is often the file's page 6).
  The reader strips markers out, shows dividers, names the page a search
  hit is on, and opens that page in the scanned view.
- **Find in book** — the page views are canvases, so the browser's Ctrl+F
  finds nothing; the text view carries its own search. Matching allows
  for what extraction does to words: `near- ness` from a line break,
  `near ness` from kerning, soft hyphens, doubled spaces. Ctrl+F on a
  book with a text version switches to it and focuses the box.
- **Upload form fills itself** from the book: title, author, category,
  languages. Titles are scored against the book's opening pages (a
  cataloguer's shorthand like "Clim. Ladder, tr.Lazarus Moore" isn't
  printed in the book); an author is only filled when its **surname**
  appears in the text, so "Janice" — whoever made the PDF — is rejected.

### Disclosures
Sign-up note about parish email; a **Parish Accounts** section in the
privacy policy; the account page shows a locked "Parish Administration
Emails" box beside the optional one.

## Tooling added

- **[scripts/list-mega-folder.mjs](../scripts/list-mega-folder.mjs)** —
  lists *and downloads* a public MEGA folder, decrypting MEGA's node keys
  and attributes with the key from the share link. No account, no
  install. Resumable (skips files already present at the right size).
  ```bash
  node scripts/list-mega-folder.mjs "<link>" --json out.json
  node scripts/list-mega-folder.mjs "<link>" --download library-incoming/prayers --folder "Prayers and Liturgical"
  node scripts/list-mega-folder.mjs "<link>" --download library-incoming/big --name "Catacomb"
  ```
  **Beware `--folder ""`** — an empty filter matches everything and
  starts pulling all 8.6 GB.
- **[scripts/shrink-pdfs.py](../scripts/shrink-pdfs.py)** — needs
  `python -m pip install --user pymupdf` (already installed). Downsamples
  over-resolved pages and re-encodes lossless page images as JPEG, only
  swapping an image when the result is ≥20% smaller. Handles two distinct
  cases found in this archive: pages already at 76 DPI but stored as
  lossless PNG (the waste is the encoding), and 603-DPI bilevel archival
  scans (the waste is resolution). Originals are never modified; results
  go to `_shrunk/`.
  - Measured: Death to the World, 11 issues, **97 MB → 33 MB (2.9×)**,
    page counts and page sizes verified identical.
  - *Russia's Catacomb Saints* (648 pages, 603 DPI bilevel, 87 MB) was
    still being re-run when this was written — first attempt gave 59 MB
    before bilevel handling was added.
