## Cloudflare R2 — the move, half done

**Why:** 10 GB free (against Supabase's 1 GB), and downloads cost nothing
ever, so reading books stops eating a monthly allowance. Tina approved on
25 Aug. Nothing changes for parishioners — same pages, same links, same
reader.

### What is already written

- **[functions/api/library/file.ts](../functions/api/library/file.ts)** —
  new. Serves PDF bytes from the R2 binding `LIBRARY_BUCKET`, enforcing
  the same visibility rules as before (anon → public only, members →
  non-hidden, admins → everything; `catechism/` keys follow the lesson
  rules). Honours Range requests so PDF.js can page through a big book.
- **[functions/api/library/pdf.ts](../functions/api/library/pdf.ts)** and
  **[functions/api/catechism/pdf.ts](../functions/api/catechism/pdf.ts)** —
  now check R2 first (`LIBRARY_BUCKET.head(key)`) and return
  `/api/library/file?key=…` when the book is there; otherwise they fall
  through to the Supabase signed URL exactly as before.

**Everything degrades safely.** With no binding present, `LIBRARY_BUCKET`
is undefined, every path falls back to Supabase, and the site behaves
precisely as it does today. This was deliberate after an earlier mistake
the same day — deploying code that selected a column migration 016 had
not yet created took the text view down until the migration ran. Never
require infrastructure that isn't there yet.

### What is NOT yet written

1. **The copy step.** Plan: an admin-only endpoint that takes one book
   id, streams it from Supabase into R2 through the binding, and reports
   back — driven by a button on `/admin/library/` that loops with
   progress, the same shape as the text-extraction backfill. Doing it
   server-side avoids putting any keys on Tina's machine. Must be
   resumable and skip books already copied.
2. **Writing new uploads to R2** in
   [functions/api/admin/library/index.ts](../functions/api/admin/library/index.ts)
   and the catechism uploader, plus deleting from R2 in the delete paths.
3. **Testing**, which cannot happen until the binding exists.

### Tina's two dashboard steps (not yet done)

1. **Create the bucket.** dash.cloudflare.com → **R2** in the left
   sidebar → enable it (this is where a payment method is required; at
   this size nothing is charged) → **Create bucket** → name it
   `library` → location Automatic.
2. **Connect it to the site.** Workers & Pages → **stjohnrgv-website** →
   Settings → **Bindings** (older UI: Functions → R2 bucket bindings) →
   Add → **R2 bucket** → Variable name **`LIBRARY_BUCKET`** (exactly
   that) → bucket `library` → Save. Apply to Production *and* Preview.
   A redeploy is needed before a new binding takes effect.

Keep the Supabase copies until the R2 path is proven; only then clear
them to free the 1 GB.

## Built on 24–25 August

### Catechism lessons — migrations 012, 014
`/admin/catechism/` uploads a lesson PDF; it appears at once under **My
Learning** on `/account/`, read at `/account/lesson/?slug=…`. Optional
"Email members" announces it to everyone opted into communications —
sent in the background, one address per message, paced for Resend's rate
limit. Posted/draft states; `catechism_lessons` table.

### Parish mailer — migrations 013, 014
`/admin/email/` writes to one member, several, or everyone with an
account. Any message with more than one recipient is addressed TO the
parish identity with everyone on **BCC** (recipients can read a To
header, so this is a privacy matter, not a nicety), batched at 49 per
message. A **Send as** dropdown picks the parish office or Fr. Antonios,
which sets From, Reply-To and the visible To. Every send is recorded in
`parish_emails`. Deliberately ignores `opt_in_communications` —
registration is the permission; that flag governs only the automatic
lesson announcements.

### Two hubs
`/admin/` and `/account/` both: a quick-jump bar over folding sections
that remember what you leave open, jumps that land instantly rather than
gliding (`<html data-instant-scroll="true">`, which the layout's
back-to-top button honours).

### Calendar fasting banner
Above the date: fast day / fish allowed / no fast, with the season and
rule, parsed from the Holy Trinity calendar's own `headerfast` line —
the parish and the calendar app can never disagree. Season and rule split
at the **last** ". " because "Nativity (St. Philip's Fast)" contains one.

### Library
- **Search** on `/learn/library/` (title, author, description, category,
  language; multi-word any order; accents fold) and on `/admin/library/`
  with filters for visibility and text state.
- **Text extraction** — migration 015. Each PDF's text is pulled out *in
  the admin's browser* with PDF.js at upload, and stored. A backfill
  button does books uploaded earlier. Scans yield nothing and are marked
  `text_status = 'empty'` so they're never retried; **13 books** failed
  outright (filter: "Failed to read").
- **Page numbers** — migration 016. Extraction writes `␞label|pdfPage␞`
  markers using the PDF's own page labels where present, so a citation
  gets the *printed* page (a book's page 3 is often the file's page 6).
  The reader strips markers out, shows dividers, names the page a search
  hit is on, and opens that page in the scanned view.
- **Find in book** — the page views are canvases, so the browser's Ctrl+F
  finds nothing; the text view carries its own search. Matching allows
  for what extraction does to words: `near- ness` from a line break,
  `near ness` from kerning, soft hyphens, doubled spaces. Ctrl+F on a
  book with a text version switches to it and focuses the box.
- **Upload form fills itself** from the book: title, author, category,
  languages. Titles are scored against the book's opening pages (a
  cataloguer's shorthand like "Clim. Ladder, tr.Lazarus Moore" isn't
  printed in the book); an author is only filled when its **surname**
  appears in the text, so "Janice" — whoever made the PDF — is rejected.

### Disclosures
Sign-up note about parish email; a **Parish Accounts** section in the
privacy policy; the account page shows a locked "Parish Administration
Emails" box beside the optional one.

## Tooling added

- **[scripts/list-mega-folder.mjs](../scripts/list-mega-folder.mjs)** —
  lists *and downloads* a public MEGA folder, decrypting MEGA's node keys
  and attributes with the key from the share link. No account, no
  install. Resumable (skips files already present at the right size).
  ```bash
  node scripts/list-mega-folder.mjs "<link>" --json out.json
  node scripts/list-mega-folder.mjs "<link>" --download library-incoming/prayers --folder "Prayers and Liturgical"
  node scripts/list-mega-folder.mjs "<link>" --download library-incoming/big --name "Catacomb"
  ```
  **Beware `--folder ""`** — an empty filter matches everything and
  starts pulling all 8.6 GB.
- **[scripts/shrink-pdfs.py](../scripts/shrink-pdfs.py)** — needs
  `python -m pip install --user pymupdf` (already installed). Downsamples
  over-resolved pages and re-encodes lossless page images as JPEG, only
  swapping an image when the result is ≥20% smaller. Handles two distinct
  cases found in this archive: pages already at 76 DPI but stored as
  lossless PNG (the waste is the encoding), and 603-DPI bilevel archival
  scans (the waste is resolution). Originals are never modified; results
  go to `_shrunk/`.
  - Measured: Death to the World, 11 issues, **97 MB → 33 MB (2.9×)**,
    page counts and page sizes verified identical.
  - *Russia's Catacomb Saints* (648 pages, 603 DPI bilevel, 87 MB) was
    still being re-run when this was written — first attempt gave 59 MB
    before bilevel handling was added.

## Standing notes

- **Never push or deploy without asking.** Commits are fine unasked.
- **Verify deploys by page content, not status code** — this site answers
  unknown URLs with 200, and `to-top` matches `back-to-top`. Both caught
  me out on 25 Aug.
- The parish is a preservation project first: Fr. Antonios asked for the
  books to exist in more than one place. Readership is not the point.
